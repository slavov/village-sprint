The 5-step framework
  1. Repeat the problem in your own words
  2. Ask 2–3 clarifying questions — constraints, edge cases, input size
  3. Think aloud — state the approach and why, before any code
  4. Narrate while coding — no silent stretches
  5. Trace a small example when stuck — line by line, out loud

Why this works
  • Streak, not deadline. No end date to run out — loss aversion keeps a running streak more motivating than a shrinking countdown ever was.
  • Three small reps beat one big one. Interleaving Algorithms, Kotlin and System Design daily (vs. blocking by topic) improves long-term recall — it's harder in the moment, better a week later.
  • The re-solve queue is retrieval practice. Reading a solution teaches you nothing durable; being forced to reproduce it cold days later is what makes it stick (the testing effect).
  • Two lines a day beats a long journal. Cheap, specific reflection you'll actually keep doing — friction kills the fancy version.
  • The board is a visible chain. Seeing the pattern of done days is its own reward — don't break the chain.
